模型与训练配置

实现采用 causal attention、RoPE、RMSNorm 和 SwiGLU；支持 embedding/output 权重共享，以及 top-k sparse MoE。

仓库里的小规模训练记录：2 层、宽度 32、4 个 attention heads、4 个专家、每个 token 选 2 个专家，共 58,784 个参数。输入是重复的 0–31 整数 token 序列，训练 80 步，用于检查优化与梯度链路。训练入口也支持加载自己的 .npy token 数据。

Questions I kept coming back to

01Embedding 到底是在算什么？为什么不直接继承 nn.Embedding？

实现与张量

Embedding 本质上是一张可训练的查找表。词表大小为 V、维度为 D 时，表的形状是 (V, D)；输入 token_ids 的形状是 (B, T)，查表后就是 (B, T, D)。

如果自己持有这张表、自己实现 forward，继承 nn.Module 并把权重注册为 nn.Parameter 即可。若继承 nn.Embedding，就要按它的构造函数传入词表大小和维度。这里容易混淆的是“使用现成层”和“自己实现这个层”。

E[token_ids]  # (B, T) → (B, T, D)

02Linear(3, 2) 的权重为什么是 (2, 3)，不是 (3, 2)？

实现与张量

构造参数描述的是输入维度和输出维度；权重的存储顺序是另一回事。每个输出单元需要 3 个输入权重，2 个输出单元就组成 2 行、3 列。

如果输入按行存放，x 是 (..., 3)，前向计算 x @ W.T，输出就是 (..., 2)。判断有没有写反，最好把一次矩阵乘法的形状展开，而不是死记参数名。

(..., 3) @ (3, 2) → (..., 2)
# 本题链接
03SwiGLU 有三个矩阵，它们分别在做什么？

实现与张量

两个矩阵把同一个输入从 D 投到 F：一个分支经过 SiLU，作为门控信号；另一个分支提供被调节的内容。两者逐元素相乘后，第三个矩阵把 F 投回 D。

因此 w1 和 w3 的层构造都是 Linear(D, F)，w2 是 Linear(F, D)。门控不是选出一个离散 token，也不是 attention；它是在特征维度调节信息。

out = W2(SiLU(W1(x)) * W3(x))
# 本题链接
04交叉熵里为什么有两个求和？one-hot 不是已经消掉求和了吗？

损失与数值

one-hot 只让“对类别加权的交叉熵求和”剩下正确类别那一项。正确类别的概率仍由 softmax 定义，而 softmax 的分母要对整个词表求和。

此外，多 token 训练还要把各个预测位置的损失求和或平均。词表轴 V 上的归一化，与 B×T 个位置上的平均，是两件事。

loss(position) = logsumexp(logits) - logits[target]
# 本题链接
05为什么 logits[:, target] 不是“每一行取正确的那个词”？

损失与数值

它的含义是：在每一行都取 target 里的所有列。假设 logits 是 (3, 5)，target 是 [1, 0, 4]，结果会是 (3, 3)，而不是三个数。

真正需要的是 (0,1)、(1,0)、(2,4) 这三个坐标。把行号和列号配对，或沿词表轴 gather，才是每个位置取自己的目标。

logits[torch.arange(3), target]  # shape: (3,)
# 本题链接
06keepdim=True 到底保留了什么？

损失与数值

它保留被归约的轴，但把长度变成 1。例如 (S, V) 沿词表取最大值，保留维度得到 (S, 1)，不保留则得到 (S,)。

广播从最右边对齐。(S, 1) 可以自然地从每一行的 V 个元素中减去一个数；(S,) 会尝试对齐最后的 V 轴，可能报错，也可能在维度恰好相等时悄悄算错。

shifted = logits - logits.amax(dim=-1, keepdim=True)
# 本题链接
07softmax 已经减了最大值，为什么再取 log 还可能出问题？

损失与数值

减最大值主要防止 exp 上溢，但很小的概率仍可能下溢成 0。若先算概率再取 log，已经丢失的信息无法恢复。

例如 logits=[0,-1000]，第二类的真实 log 概率约为 -1000；浮点计算中 softmax 的第二项却可能成为 0。直接用 logsumexp 减去目标 logit，就不用先保存这个极小概率。

loss = torch.logsumexp(logits, dim=-1) - target_logit
# 本题链接
08RMSNorm 为什么不能直接用 torch.var？

损失与数值

RMSNorm 归一化的是均方根：sqrt(mean(x²)+eps)。方差先减去均值，测量的是围绕均值的波动，数学对象不同。

例如 x=[2,2]，均方根是 2，方差却是 0。把 var 放进 RMSNorm，即使关闭无偏修正也不对。实现时还要注意 eps 在根号内，以及低精度输入用 float32 做归约。

y = x * rsqrt(mean(x*x) + eps) * weight
# 本题链接
09Adam 的“初始化修正”和“归一化”是同一回事吗？

训练与架构

不是。m 和 v 从 0 开始，前几步的指数移动平均会偏向 0。偏差修正除以 1−βᵗ，是为了补偿这一初始化效应。

另一步是用 sqrt(v_hat)+eps 缩放 m_hat，让每个参数根据自己的历史梯度平方尺度调整步长。比如梯度始终为 2、β₁=0.9，第一步 m=0.2，修正后 m_hat=2。这里不是把所有参数的梯度统一归一化到长度 1。

m_hat = m / (1 - beta1**t)
v_hat = v / (1 - beta2**t)
update = lr * m_hat / (sqrt(v_hat) + eps)
# 本题链接
10残差块写成一个长表达式，会不会把 attention 算两遍？

训练与架构

会。若在两个子表达式里都调用 attention(norm(x))，框架通常会执行两次调用，不会自动把它们当成公共子表达式缓存。

pre-norm block 可以明确分两步：先得到 attention 残差后的 h，再把 h 送入第二个 norm 和 FFN。这样既清楚又避免重复计算；有随机操作时，两次调用甚至未必相同。

h = x + attention(norm1(x))
y = h + ffn(norm2(h))
# 本题链接
11最后一层 hidden state 和词表 logits，不就是差一次矩阵乘法吗？

表示与状态

是，最后一层输出经过最终归一化后，通常通过线性投影得到词表 logits。但 logits 仍是一整组连续数；从它们采样或 argmax 得到一个 token，才是明显的信息压缩步骤。

不能笼统说 hidden state 一定比完整 logits 信息更多：若输出矩阵满列秩且已知，精确 logits 在数学上可能足以恢复输入向量。实际区别还涉及维度、数值精度、接收模型接口和训练目标。连续向量也不会自动成为一个好的通信消息。

h ∈ R^D → logits = W_out h ∈ R^V → token_id

12最后一个 token 看过整个前缀，就等于整个前缀的总结吗？

表示与状态

不等于。“可以关注前缀”说明信息通路存在，不保证模型把所有有用信息都编码到了最后一个向量里。下一词预测训练主要奖励有助于预测的表示。

如果把这个向量当通信内容，需要用接收方任务来检验：与文本消息、多位置表示、随机向量相比如何？删掉或者打乱消息会怎样？是否需要通信相关的训练目标？能访问历史，和能充分总结历史，是两种不同的能力。

13steering 撤掉以后，第一个生成词为什么还不能证明残留？

表示与状态

因为自回归预测错开一位。长度为 L 的 prompt，最后一个位置的 logits 用来生成第一个新 token；如果 prompt 阶段仍开着 steering，这个 token 就仍来自受干预的计算。

第一个新 token 被送回模型之后产生的 logits，才预测第二个新 token。研究撤掉后的状态效应，还要控制第一个 token 本身改变了后续上下文这个因素。固定 token 序列评分与自由生成回答的是不同问题。

prompt position L-1 → generated token 1
generated token 1 position → generated token 2
# 本题链接
14KV cache 是输入的信息，还是参数的信息？

表示与状态

两者共同决定。某一层的 K、V 由该层的 hidden states 和投影权重计算得到，而 hidden states 又依赖输入以及前面各层的计算。

因此，同一串 token 换一套参数，缓存可能改变；同一套参数换输入，缓存也可能改变。复用旧缓存是否可行，取决于改了什么以及误差会怎样传播，不能把它当作完全独立于模型的文本存储。

K_l = H_l W_K,l
V_l = H_l W_V,l

15embedding 和输出头共享权重，究竟共享了什么？

项目延伸

输入查表与输出词表投影使用同一个 Parameter，而不是两张初值相同的表。词表大小 V、模型宽度 D 时，相比独立输出头可少 V×D 个参数（无 bias 时）。

梯度会从输入和输出两条计算路径汇总到同一个参数上。它约束两种用途共用一个表示空间，但不能保证质量提升。当前项目用参数身份、参数量差值和存档恢复检查这一点。

lm_head.weights = token_embeddings.weight

16MoE 的 top-k 到底在选词，还是在选网络？

项目延伸

选的是专家网络。每个 token 的 hidden state 经过 router 得到专家分数，选中 k 个 SwiGLU 专家，把它们的输出按路由权重相加。它与从词表里挑 top-k token 的采样不是一回事。

总参数量包含所有专家；单个 token 只经过其中一部分。参数变多不等于速度一定快：分发、聚合、负载不均衡和硬件利用率都影响实际速度。本项目采用显式 sparse dispatch，便于检查计算过程。

token hidden state → router → selected experts → weighted sum
